## 选号与干净度：先审计，再开跑

- 只引表格和实测数据，不凭内容语言推注册地。曾有教训：把“日文营销视频”
误推成“日本注册地”，实际同批全是美区号。
- 干净度分档要 Studio 实读：公开页 videoCount 不可靠，零视频可能是私密 spam。
A 级只认两类：有真实分发证据的号、从未发过视频的真空号；其余 spam 史先放着不动，
不清理、不设私密、不原样重发旧集数。
- 新号前 72 小时只做轻量人工节奏，绝不上高频自动化。新号高频自动化进手机号验证
checkpoint 是实测教训，不是理论。
- 1 个 IP 挂 ≤3 个活跃号是安全线，超 5 个风险陡增；固定 IP 绑号不轮换；
机房 IP 信任分低于住宅 IP，靠行为纪律补，不要靠换 IP 掩盖行为问题。

## 代理与出口：按账号查，不许凭感觉

- 账号级代理：每个号有自己的 socks5 出口，检查脚本要读账号自己的 proxy 配置，
无配置才用默认出口；一次性脚本里写死的旧出口，跑已迁号前先改或先确认。
- 发布前验出口：上传前后都要实测出口 IP 与账号绑定的出口一致，不一致就停手，
不要“先发了再说”。出口硬门槛是按号定的，不是全群一个数。
- 隧道与浏览器写法各不相同：Camoufox 的 socks5 与 curl 的 socks5h 在同一隧道上
表现可能完全相反，浏览器挂了不代表 API 通道挂了，curl 走 TikTok API
（评论 / 粉丝）可以是浏览器挂掉时的兜底，但不要把它当成常规发布通道。
- VM 重建会丢 /etc 服务与 pip 全局包，发布前先查工具在不在（如 autotok），
缺了先重装；指纹浏览器要用项目指定的 venv，不要用系统 python 碰运气，
曾出现命名空间目录假成功、到别的目录就 ModuleNotFoundError。

## 视频生产：问题清单（按阶段查）

### 构图：出框即打回
- 现象：青蛙出框、鸭子半身出左边缘、玻璃房被切。病灶不是没定规矩，
是验收时漏执行了构图这一关。
- 处理：全景 / 中景、主体与关键道具完整入框、四边留边；生成提示锁
static camera / no zoom in；图生视频阶段镜头会自行推近，质检必须逐镜看构图，
不能只看第一镜。
- 验活：成片逐镜过一遍，任何一镜主体出框就重拍该镜，不靠后期裁切救。

### 剧本与梗：骨架归 IP，梗只是调料
- PvZ 固定四段：① 左右阵营对战开局 ② 僵尸出新花样压制
③ 植物用“场外现代手段”翻盘 ④ 升级武器反杀收尾。
每集轮换僵尸新花样 / 求生手段 / 升级武器 / 默片梗桥段，
求生手段池开放轮换，禁固定成“每集掏手机问 AI”（掏手机位是未来广告位，先通用界面）。
- 梗只收默片型：关声音、纯画面成立才收；梗只许 1–2 镜桥段，不许梗吃掉骨架。
- EP03 否决立下的三条：① 赢家才推进、输家趴下退场 ② 武器先输 → 主动去找 →
拿到火箭筒级面积武器 → 杀回来 ③ 结尾只许胜负分明（趴地 / 逃跑 + 庆祝）。
- 治愈线笑点机制：睡前微仪式 × 一件大一号日用品 × 一个安静的落空或微发现；
主角必须是笑料的施动者，结尾必须有一幅包袱画面；“只是萌”不算过关。
- 复刻铁律：先下原片 → 逐帧拆分镜表 → 照表换人 / 换产品重拍，
不许凭一张截图自己编结构。原片没拆完就开拍，等于没复刻。

### 字幕、音频、拼接：不要手抄、不要覆盖原声
- ASS 字幕不要手抄 Style 字段顺序：Format 头漏字段会让字幕整屏旋转 90° 贴左边缘。
处理：直接复用已冻结的 24 字段 header，不要重抄。
- 拼接：首尾帧续接后每个接点切掉 0.5 秒重复帧；原声优先保留，禁用 -an 覆盖；
每条成片全程抽查音量（多个时间点），有问题才处理，不要默认加 BGM 盖过去。
- 语音 / 转录工具：跑前先清掉会坏事的环境变量（如含括号条目的 no_proxy），
并开离线模式；环境变量在 VM 重建后可能变化，出错先查环境再查模型。
- 媒体工具先验活再生产：ffmpeg 曾出现滤镜层整体 EPERM、文件写 0 字节，
进程 / 磁盘都正常。恢复后先跑一条 testsrc 抽帧验活，验活不过不进生产。

### 生图与角色：只学语法，不碰形象
- 角色锁定靠参考图锚定生成，禁纯文本现编人物；人物、配音、风格一经拍板就冻结，
后续生产 cron 与 QA 都要对着冻结项查。
- ChatGPT 分工：开放式叙事与生图讨论给 ChatGPT，格式剧本按公式填分镜表由助手写；

## 发布、审核与数据：发出去不等于过审

- TikTok 定时发布曾被拒收（Creator 切不了、定时被拒），处理是改即时发布，
不要反复重试同一个定时参数。
- 新上传先是 Content under review，约 4–15 分钟才转公开；验证落地必须复查，
只看“上传成功”不算过审。
- Studio 删除不要用菜单 JS 点击（曾不生效），须真实鼠标点击，删完复验 GONE。
- 发布闸是不可逆动作：删视频、重传、开闸发布必须等明确拍板，拍板前一律按“不做”处理；
删掉重发的视频，重发前把英文配文给用户过目。
- 配文：全英文、简洁、一个中文字符都不许出现；固定 Save CTA 类结尾按线执行；
配文末尾加 AI-generated content 标注行，上传工具没有官方 AIGC 开关可开，
上传端不做额外标注。
- 数据唯一来源：单条播放 / 留存 / 完播 / 流量来源以 Studio 网页版实读为准，
不要用公开页计数推断。诊断：断崖在 0–3 秒判 hook，中段判结构；
每周方向决策（继续 / 微调 / 换方向）须用户拍板后才进生产 cron。

## 评论、粉丝与回关：只认两个来源

- 新粉丝来源只能是：① 通知弹窗“started following you” ② /followers 列表（最新排序）。
严禁从 profile 页全量收集链接，会混入“Following accounts”挂件导致误回关陌生人。
- 粉丝模态首轮为空可能是假空，判“无新粉丝”前必须复检一次；
followers 计数器显示 0 不可信，模态实际可能有粉丝。
- 回关只点 Follow / Follow back 按钮，点完复读状态确认服务端生效，
不要凭按钮变色就认定成功。

## 双向审片：自审不算终审（2026-10-24 更新，替代旧自审模式）

- 教训：以前是 kcj95445 自己生成、自己审，构图出框、包袱没落、AI 瑕疵这类问题
  自己看不出来，成片总带着问题出去。自审只能算预检，不能算终审。
- 方向一（别人 → kcj95445）：其他机器人做好的视频发给 kcj95445 审，
  kcj95445 必须仔细看、逐镜看，按 6 项清单（构图 / 前 2 秒 hook / 配文全英文 /

- 方向二（kcj95445 → 机器人）：kcj95445 自己生成的视频，必须找群里机器人轮换主审，
  外审没回来或说“需改”，一律不发布、不交付；改完重审该问题，不凭感觉直接过。
- 派活与轮换、备份、SLA 细节见 `local-feishu-group-collab`；总 skill 只定方向，
  不重复写排班表，避免两处规则打架。

## 交付与文件：送达才算数

- 飞书文件上限 30MB，超限会被静默拒收、pending 无限重试、用户端毫无动静。
发大视频前先压到 ≤28MB（720p、crf 28 类参数），写 pending 后等 60 秒，
确认已移入 sent 且 serve.log 无 send error，才算送达。
- 交付包：视频 + 封面 + 中英配文（按交付方要求）；用户要在手机上复制的物料，
默认分条短消息、一条只做一件事。
